SQLite

Flutter is loosely based on Android, so it inherits SQLite from how Android implements it. However, SQLite uses a lot of common code (called boilerplate) to set up a database and queries. There are newer libraries that now generate the database code for you so it is easier to manage. In Android, there is the ROOM database library, and there is a similar library for Flutter called Drift library: https://pub.dev/packages/drift
The Drift library can be used for all platforms, including Web Applications. To get started, have a look at this tutorial: https://r1n1os.medium.com/drift-local-database-for-flutter-part-1-intro-setup-and-migration-09a64d44f6df

Follow the instructions from the website Pub.dev for installing the required library in pubspec.yaml. Then open a new file to write the SQL create table statment for the table you will create to store your items. The file must have end with .drift

Within the .drift file, write your table creation statement in SQL: 

CREATE TABLE User (
    id INT NOT NULL PRIMARY KEY,
    username TEXT NOT NULL,
    music_style TEXT NOT NULL,
    favorite_song INT NOT NULL
) As UserTable;

Also, write your insert, delete, and query functions as stored procedures in a separate queries.drift file: 

saveUser: INSERT INTO Users (id, name) VALUES (:id, :name);
getAllUsers: SELECT * FROM Users;

Next, create a dart file to create a Database class for your project: 

    import 'dart:io';

import 'package:drift/drift.dart';
import 'package:drift/native.dart';
import 'package:path/path.dart' as p;
import 'package:path_provider/path_provider.dart';

part 'appDatabase.g.dart';   //<< This tells flutter where to put the generated code later.

@DriftDatabase(
  include: {'tables.drift'},   // << This is your .drift file you wrote
)
class AppDatabase extends _$AppDatabase {

  static AppDatabase instance() => AppDatabase();

  AppDatabase() : super(_openConnection());

  @override
  int get schemaVersion => 1;
}

LazyDatabase _openConnection() {
  return LazyDatabase(() async {
    final dbFolder = await getApplicationDocumentsDirectory();
    final file = File(p.join(dbFolder.path, 'db.sqlite'));
    return NativeDatabase.createInBackground(file);
  });
}

Once you have finished this file, you must generate the table creation code in dart by translating your .drift SQL statements into dart code. run the command: 

dart run build_runner build

This will put the generated code in the file listed by the part command.

If ever you modify the SQL table creation statement, to add or remove a column, or change the data type of a column, you must handle the data migration path. You could have some apps already installed on some customers phones so you need a way for their data to be migrated to the new database schema.

  • Create a DAO class:
    @dao
abstract class PersonDao {
    //this performs a SQL query and returns a List of your @entity class
  @Query('SELECT * FROM Person')
  Future<List<Person>> findAllPersons();


    //This performs a SQL delete operation where the p.id matches that in the database
  @delete
  Future<void> delete(Person p);

    //This performs a SQL insert operation, but you must create a unique id variable
  @insert
  Future<void> insertPerson(Person person);
}
    The @insert annotation will generate the necessary SQL code to insert the Person object into the database. It will map the class' variables automatically to database columns. Likewise, the @Query annotation will create the SQL query code to find all Person objects in the database. It will return a List object with all the objects it found.
    All the functions return Future objects meaning that these queries are all asynchronous. You either have to use await when calling these functions, or follow the function calls with .then( obj { } ) to get the data back.

    Lastly, when you are using databases in your application, you normally load all the data as a first step. When you are creating your List< > object, you would then also run your query to load items into that list from the database. A good place to do this is in the initState() function since you are indeed initializing the state of your application.

    Please explore more of the documentation in the tutorial. Let's now go over the steps in an example by modifying the ListView example from last week. Whenever you add something to the List< >, you should also insert into the database. Whenever you remove something from the List< >, you should also delete from the database. Whenever you start the application, you should initialize the List< > by running a query. This will run asynchronously so when the results return from the database, you can call setState() to cause your GUI to redraw.
