Creating new pages

Creating new pages follows the same pattern.

  1. Create a new file in the /lib folder and call it OtherPage.dart
  2. Everything that appears on a page in Flutter is a subclass of Widget. For an entire page, you create class that here we will call OtherPage that extends StatefulWidget. This StatefulWidget class inherits one function called createState. It returns a templated state object:
    class OtherPage extends StatefulWidget {
        @override
        State<OtherPage> createState() => OtherPageState();
    }

and then below that class declaration, you can create another class that extends State<OtherPage> . It is important that what goes in the angle brackets is the name of the State class that you declared above. In this case, it's OtherPage 

    class OtherPageState extends State<OtherPage>
    {
        @override
        Widget build(BuildContext context) {

        return  ; //create a layout for this page using Column, Row, Stack() etc
    }

This State class should override the build(BuildContext context) function. This function should return a Widget object which is how to draw this object on screen. This would normally have a Column, Row, Stack etc. to arrange the components for this page. For now, we can just return a Text("Welcome to other page").

Named routes

In order to support web sites, we can use named routes. Named routes let your app behave like a website:

  • /pageOne For going to page one
  • /pageTwo For going to page two

In the MaterialApp( ) declaration of your app, where you set removed the debug banner, you can also define the routes to your different pages: 

    MaterialApp(
        title: 'Named Routes Demo',
        initialRoute: '/',
        routes: {

            '/': (context) => const FirstScreen(),
            '/second': (context) => const SecondScreen(),
            '/otherPage': (context) => OtherPage(),
        },
    )

On the left side, you define the route's name followed by : and then the constructor of a page object that should be loaded when that route is loaded.

How to launch a route transition

Now to get to this page within an app, use the function: Navigator.pushNamed( ). The context parameter means the current page and it's an object that defined as a BuildContext in the build function 

    Navigator.pushNamed(  context,"/secondPage" ), //This NamedRoute string must be one of the named states

If you are using a web browser, then you can type the route into the address bar: 

 https://localhost:???/secondPage

To go back to the previous page, use Navigator.pop(). It will return you to the previous page. 

{
  Navigator.pop(context);
}
