Responsive Layouts

Normally, a tablet is held in landscape mode, meaning that the width is bigger than the height: In Flutter, you can call a function to find out what the width and height of your device is in pixels: 

    var size = MediaQuery.of(context).size;
    var height = size.height;
    var width = size.width;

In Android, if the width is more than 720 pixels, then there is enough room to fit a listView on one side, and details on the other side. This is called the Master-Detail pattern: https://developer.microsoft.com/en-us/azure-devops/components/master-detail

To check if you are landscape mode, just check if the width is greater than the height. If that's true, then verify that the display width has at least 720 pixels: 

 if( (width>height) && (width > 720)) {

}

In the Scaffold layout, you can't put an if() statement as a parameter to the body:, so we'll create a function called reactiveLayout which will be a function that will have the if statement above, and returns a Widget component:

    Widget reactiveLayout()
    {
        if( (width>height) && (width > 720)) {
        }
    }

In this case, you can put your listView on the left side, and a details page on the right side for when the user selects something from the list: 

{
    Row( children:[
        ToDoList(), //Left side
        DetailsPage() //Right side
    ])
}

However the ToDoList() function and DetailsPage() don't exist yet because they are functions that you must write. Since everything that can be shown on the screen is a type of Widget object we can declare the following functions so that they return a widget: 

    Widget ToDoList() {

    }

    Widget DetailsPage() {

    }

We also need a way to space out the List and DetailsPage so that the ListView takes a fixed width on the Left side, and the DetailsPage is on the rigth side. There is an Expanded( ) class that lets you specify a flex parameter: 

Expanded(
      flex: a, // takes  a/(a+b)  of available width
      child: ToDoList(),
    ),
Expanded(
      flex: b, // takes b(a+b) of available width
      child: DetailsPage(),
    ),

For showing the selected item in the DetailsPage, we'll create a variable to store which item in the list has been selected by the user. This should be nullable because it's possible that the user hasn't selected anything yet: 

var selectedItem:ToDoItem ? = null

Then when the user selects an item from the list, you set the variable to be the object represented at that row. 

Widget DetailsPage() {
    if(selectedItem != null){
     //Show some layout to represent the object's variables
    }
}

That should take care of the code for the tablet version of your application. Last is to take care of the phone version of your code. Normally a phone would show a listView using the whole screen. Then when the user selects something, then the next screen shows the details of what was selected: 

    if(selectedItem == null){
        ToDoList() // reuse the code from the tablet Left side,
    }
    else
    {
        DetailsPage(); //reuse the code from the tablet Right side
    }

If the user selects something from the ListView, there should be some way to set the selectedItem variable back to null, so that there is no longer something selected. This can either be done by putting some sort of "Delete" or "Clear" button on the details page, or using the AppBar or BottomNavigationBar to present a button that clears the selected item.
