SQLite

Flutter is loosely based on Android, so it inherits SQLite from how Android implements it. However, SQLite uses a lot of common code (called boilerplate) to set up a database and queries. There are newer libraries that now generate the database code for you so it is easier to manage. In Android, there is the ROOM database library, and there is a similar library for Flutter called the Floor SQLite library: https://pinchbv.github.io/floor/
The Floor library can be used for all platforms except for Web Applications. To get started, have a look at this tutorial: https://pinchbv.github.io/floor/getting-started/

Before we begin, we will need to create an entity, or model class. This is just a class that will store data about the objects in our project. Entity, or model classes are typically something like Car, Person, Date, Assignment, etc. They are the kind of classes that are the building blocks of an application, which represent the most basic object being used in your project. For our To-Do list, our entity class should be a ToDoItem, with just a String for the name of the item.

If we follow the tutorial listed above, the steps are basically:

  1. Add the following dependencies to pubspec.yaml: 
    dependencies:
  flutter:
    sdk: flutter
  floor: ^1.4.0

dev_dependencies:
  floor_generator: ^1.4.0
  build_runner: ^2.1.2
  2. Create an Entity by adding the annotations @entity above the class that will go in the database, and then add 
    @primaryKey
  final int id;
    to the class to store the database id.
  3. Create a DAO object:
    @dao
abstract class PersonDao {
  @Query('SELECT * FROM Person')
  Future<List<Person>> findAllPersons();

  @delete
  Future<Long?> delete(Person p);

  @insert
  Future<Long> insertPerson(Person person);
}
    The @insert annotation will generate the necessary SQL code to insert the Person object into the database. It will map the class' variables automatically to database columns. Likewise, the @Query annotation will create the SQL query code to find all Person objects in the database. It will return a List object with all the objects it found.
    All the funcions return Future objects meaning that these queries are all asynchronous. You either have to use await when calling these functions, or follow the function calls with .then( obj { } )
  4. Create the database:
    // database.dart

// required package imports
import 'dart:async';
import 'package:floor/floor.dart';
import 'package:sqflite/sqflite.dart' as sqflite;

import 'dao/person_dao.dart';
import 'entity/person.dart';

part 'database.g.dart'; // the generated code will be there

@Database(version: 1, entities: [Person])
abstract class AppDatabase extends FloorDatabase {
  PersonDao get personDao;
}
    Make sure to change the entities: from Person to whatever object you are using in your project. You will have to run the code generator after to build the code from the annotations.
  5. Use the generated code:
    final database = await $FloorAppDatabase.databaseBuilder('app_database.db').build();

final personDao = database.personDao;
final person = Person(1, 'Frank');

await personDao.insertPerson(person);
final result = await personDao.findPersonById(1);
    You can change the filename that it uses for your database by replacing the string app_database.db' You will also have to implement your own tracking variable for the database IDs. In the example above, "Frank" had the ID of 1, however the ID should be dynamically created.
    6. static int ID = 1;

    Then, when you create Entity objects, you increment the counter: 

    final person = Person(ID++, "Frank");

    However, here the Floor library might load items from the file that have an ID already assigned that is higher than the current ID. For example, if an object in the database has an ID that is 100 for example, then your ID variable should be higher than that. In the Person constructor: 

    Person(int id, String name)
{
    if(id > ID)
        ID = id + 1;

    ...
}

Please explore more of the documentation in the tutorial. Let's now go over the steps in an example by modifying the ListView example from last week. Whenever you add something to the List< >, you should also insert into the database. Whenever you remove something from the List< >, you should also delete from the database. Whenever you start the application, you should initialize the List< > by running a query. This will run asynchronously so when the results return from the database, you can call setState() to cause your GUI to redraw.
